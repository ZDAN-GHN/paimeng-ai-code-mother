# 八要素审查检查表

对「交付给 Agent 落地实现的方案设计」逐要素检查。每个要素给出：**通过** 或 **问题**（阻塞/高/中/建议 + 证据 + 建议修法）。

审查视角始终是：**agent 只看这份方案（及它引用的文件）能否无歧义、可验证地完成交付**。

---

## 1. 目标与背景

**检查点**：
- 是否有一句话、可衡量的目标（做什么 + 交付物是什么）？
- 背景是否克制在 2~3 句，没有大段产品历史？
- 目标结果是否可验证（能判断「做没做到」）？

**反例（问题）**：
- ❌「优化生成流程，提升体验」——不可衡量，无交付物。
- ✅「新增 `POST /api/ai/generate`，输入自然语言描述，输出可运行的 Vue3 代码字符串；响应字段见第 4 节示例。」

**判定**：目标缺失 → 阻塞；目标存在但不可衡量 → 高。

## 2. 范围界定

**检查点**：
- 是否明确写了 **In**（本次交付什么）与 **Out**（明确不做什么）？
- 是否写清前置依赖（依赖哪个已有模块/接口/数据）？
- 是否避免「按现有风格」「类似上面」这类靠猜的表述？

**反例（问题）**：
- ❌ 只写「做一个生成接口」——范围无限，agent 不知道要不要做鉴权、落库、前端。
- ✅「In：后端接口 + 单测。Out：不做前端调用、不做用户鉴权、不做限流。前置：依赖 `ai` 包的 `ChatClient`（见参考 X）。」

**判定**：无 In/Out 边界 → 高（易返工）；边界内存在隐含歧义 → 中。

## 3. 现状与约束

**检查点**：
- 要新建/修改的文件是否给出**确切路径**（而非「在 service 层加个方法」）？
- 硬约束是否可执行（代码规范、构建命令、提交格式等）？
- 是否明确「不能动的东西」（如不入库的敏感配置）？

**反例（问题）**：
- ❌「在合适的位置加个 Service」——agent 可能放错包、或犹豫不动手。
- ✅「新建 `src/main/java/com/zdan/paimengaicodemother/service/XxxService.java`；遵循阿里巴巴开发手册；提交须带 Co-Authored-By。」

**判定**：关键路径缺失或写错 → 高；约束与实际项目不一致 → 高（引用失效类）。

## 4. 技术方案

**检查点**：
- **接口契约**：方法签名、请求/响应 JSON 是否有**完整示例**（不是省略号）？
- **数据结构**：新增表/字段是否有完整 DDL；复用字段是否给出确切字段名？
- **数据流**：调用链是否逐步写清（如 `Controller → Service → ChatClient → 解析 → 落库`）？
- **关键实现**：是否给出 1~2 段参考片段或核心逻辑示意？
- **取舍**：存在多个可选方案时，是否一句话说明选 A 的原因？

**反例（问题）**：
- ❌「返回 JSON 包含结果」——字段名、类型、嵌套全缺，agent 只能猜。
- ✅ 给出请求体、成功/失败响应各一个完整 JSON 示例 + 字段说明 + 异常时的错误码。

**判定**：缺接口契约/数据结构 → 阻塞（无法开工）；示例与实际实现冲突 → 高；无参考片段但契约完整 → 建议。

## 5. 任务分解

**检查点**：
- 是否拆成**原子任务**（一个任务一件事，如「建表」「写 Mapper」「写单测」）？
- 是否标注**依赖顺序**（哪些可并行、哪些必须等前面）？
- 每个任务是否有**明确产出物**（文件路径 + 行为）？

**反例（问题）**：
- ❌「完成生成功能」——不是任务，是口号，无法拆分执行。
- ✅「① 执行 `sql/create_table.sql` 追加生成记录表 DDL → ② 用 MyBatis Flex 生成器生成 Mapper（产出 `mapper/XxxMapper.java`）→ ③ 实现 Service + 单测（产出 `XxxServiceTest.java`，命令 `./mvnw test -Dtest=XxxServiceTest`）。」

**判定**：无任务分解或任务含多件事 → 高；有分解但无顺序/产出物 → 中。

## 6. 验收标准

**检查点**：
- 是否可用**命令或 curl 客观验证**（如「`./mvnw test` 全绿」「返回 200 且 body 含 `code` 字段」）？
- 是否覆盖**边界用例**（空输入、超长输入、异常分支、并发）？
- 是否避免了「界面美观」「体验流畅」这类不可判定表述？

**反例（问题）**：
- ❌「确保代码质量，运行流畅」——不可判定，无法验收。
- ✅「① `./mvnw test -Dtest=XxxServiceTest` 全绿；② `curl -X POST ...` 带合法 JSON 返回 200 且 `data.code` 非空；③ 空描述返回 400 及错误码 `PARAM_ERROR`；④ 超长输入（>5000 字）返回 413。」

**判定**：验收全部不可判定 → 阻塞；主路径可验证但边界缺失 → 中。

## 7. 风险与陷阱

**检查点**：
- 是否把**已知的坑**写明（框架解析怪癖、类型生成时机、平台限制等）？
- 是否有避免 agent 重复踩坑的提示？

**反例（问题）**：
- ❌ 无风险章节，或只有「注意安全」这种空话。
- ✅「LangChain4j 返回的 JSON 可能被 ```json 代码块包裹，需先剥离标记再反序列化；接口变更后需重跑 `npm run openapi2ts` 同步前端类型。」

**判定**：存在已知坑但未写 → 中；写了空泛风险 → 建议。

## 8. 参考资料

**检查点**：
- 是否给出**确切文件路径/链接**（而非「看下项目结构」）？
- 引用的路径是否**真实可解析**（与第 3 步现状核对）？
- 参考资料是否覆盖 agent 开工前必须读的上下文（如 `AGENTS.md`、`CONTEXT.md`、`sql/create_table.sql`）？

**反例（问题）**：
- ❌「参考现有代码实现即可」——不可解析。
- ✅「背景见 `CONTEXT.md`；表结构见 `sql/create_table.sql`；接口风格参考 `src/main/java/.../controller/AiGenerateController.java`。」

**判定**：引用路径不存在或不可解析 → 阻塞；引用存在但只给目录不给文件 → 中。

---

## 报告中的严重度速查

| 严重度 | 典型触发 | 结论影响 |
| --- | --- | --- |
| 阻塞 | 缺接口契约 / 验收不可判定 / 引用失效 / 范围无限 | 出现即 FAIL |
| 高 | In/Out 不清 / 示例冲突 / 关键路径缺失 | 出现即 PASS-WITH-FIXES（无阻塞时） |
| 中 | 缺边界用例 / 已知坑未写 / 无任务产出物 | 可 PASS-WITH-FIXES 或建议修复 |
| 建议 | 参考片段可再给 / 措辞可更精确 | 不影响结论 |
