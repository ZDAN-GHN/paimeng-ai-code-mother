# 派蒙 AI 应用工坊 · 重构共识汇总（审讯终稿）

## 一、定位与产品形态

- **受众**：不会编程但想要个人网站作品的人（大学生、个体工商户）——差异化在受众而非技术。
- **核心风险**在“简单需求 → 中型工程”的鸿沟，靠**交互设计**（模板锚定 + 线框闸门 + 结构化访谈）收敛，不靠堆 Agent 数量。
- 生成物演进阶梯：**L0 静态+内嵌数据 → L1 预览态 mock 后端（MSW 风格拦截层）→ L2 BaaS 集成 → L3 TS 全栈后端**。Java→JS 编译、浏览器内置 Java 虚拟后端：**永久删除出路线图**。

## 二、总体架构（三服务 + 边界）

| 服务                                          | 技术栈                              | 职责                                                         |
| --------------------------------------------- | ----------------------------------- | ------------------------------------------------------------ |
| **Java**（`src/`）                            | Spring Boot                         | 业务 REST、鉴权（签发 JWT）、积分/充值/会员、聊天历史、构建部署（`BuilderExecutor`）、可视化编辑器数据 |
| **TS Agent**（新建，Node）                    | Fastify + Vercel AI SDK + XState v5 | 需求访谈、线框生成、planner→coder→reviewer 工作流、工具执行、Guardrail、SSE 直连浏览器 |
| **Python RAG**（新建 `paimeng-ai-code-rag/`） | FastAPI（复用旧 agent 骨架模式）    | 检索：day-1 只读直查 MySQL few-shot；v2 引入 ingest 管道 + pgvector + 自有 schema |

**拓扑**：前端 fetch-SSE 直连 Agent（JWT 鉴权，离线验签）∥ 前端↔Java（业务）∥ Agent→Java 内部回调（结算/历史/构建触发，Bearer 服务令牌 + runId 幂等）∥ Agent→RAG（`POST /v1/retrieval/context`）。生产 nginx 单域名路由（`/api/*`→Java，`/agent/*`→Node）。**不上服务发现、不上 LLM 网关（MVP）**；网关为后续必选项，届时自托管（NewAPI/LiteLLM 类）。

**存储分工**：MySQL = 业务 + `generation_run` + 积分台账（**交易归 MySQL**）；PG = 即刻停用，RAG v2 时重启（**记忆归 PG**）；PostgreSQL run 表 checkpoint 已被 MySQL run 表取代。

## 三、Agent 设计

- **编排**：XState v5 状态机（phase：`interview → wireframe_pending → wireframe_confirmed → coding → review → building → done/failed/aborted`），快照序列化存 run 表 `context` 列；模型层 Vercel AI SDK（三档配置：快速/标准/深度，默认标准，每消息可选）。
- **checkpoint = `generation_run` 表**：run_id / app_id / user_id / phase / context JSON / milestones JSON / token_usage / 积分台账引用；断点续传 = 查最新非终态 run 续跑；同 app 并发 run 拒绝。
- **质量门禁（验收不靠角色签字靠机器）**：结构化质检分 + `npm run build` 通过 + 视觉 diff 线框；重试有界。
- **token 五层护栏**：输出硬上限（max_turns / max_output_tokens / max_tool_calls=50 先例 / 图片 4 张）按档位差异化；超限优雅收尾不硬杀；输入历史滑窗+摘要；runId 计量落库（定价校准）；用户日配额 + 单 run 熔断。**按次计费 + 硬上限 = 单次成本有界，亏损在数学上不可能。**
- **对话中断**：(a) 中止 day-1（断连感知 → 取消调用 → 保留半成品 → 历史标记 → 按里程碑退款，首文件前全额退）；(b) 续传挂 checkpoint 稳定后。

## 四、需求工程与线框

- 模板锚定 6 个（个人主页/店铺展示/作品集/预约服务/博客/活动页），day-1 提示词内置；访谈固定 5 维（受众/风格/页面/数据/交互）选择题，最多 2 轮；信息齐直接出线框。
- 线框 = 单文件 HTML（灰块+占位+可点击跳转+站点地图），**≤5 页**，快速档模型，可迭代；确认后作为 codegen 布局契约与视觉 diff 基准。**闸门纪律：未确认线框不生成。**
- **线框免费 + 独立限频**（每用户每日 N 次）；积分冻结发生在确认线框进入 codegen 时刻——闸门与用户激励同向。
- 技术栈强制选择：显式选择跳过 AI 路由，未选才“智能推荐”；枚举扩展以 BuilderExecutor 支持为前提；Agent 只提示不擅自降级。
