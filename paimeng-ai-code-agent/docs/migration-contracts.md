# 当前接口与页面迁移清单

原页面路径保留为 `/`、`/user/login`、`/user/register`、`/admin/userManage`、`/admin/appManage`、`/admin/chatManage`、`/app/chat/[id]` 和 `/app/edit/[id]`。

## 业务接口

用户接口保留注册、登录、退出、当前登录用户、公开用户详情、管理员用户详情、用户分页、管理员更新与删除，共 9 项。密码摘要不通过任何详情接口返回。

应用接口保留创建、更新、删除、详情、我的应用分页、精选应用分页、管理员分页、管理员详情、管理员更新、管理员删除、流式生成、发布与下载，共 13 项。精选条件保持优先级至少 99。所有数据库 ID 使用字符串。新增应用、用户及文本聊天历史使用与原 MyBatis Flex 1.11.1 相同 epoch 和位布局的雪花 ID，不再依赖数据库自增。已有记录保持原 ID。

历史接口保留应用历史分页（`GET /api/app/messages`）1 项；管理员的对话分页（`chatHistory/admin/list/page/vo`）与对话管理页面随旧 `chat_history` 表一起删除（2026-10-18，见 `docs/plans/pi-durable-m4.md`），管理员改为进具体应用的对话页查看。应用历史、完整工具消息和生成任务状态必须通过服务端归属校验。生成时不信任浏览器传入的其他应用上下文。

健康检查仍由 `/api/health` 提供。生成静态资源不复用旧项目的 `/api/static`，新预览由专门的隔离来源提供。这是安全边界的替换，旧静态接口不在新管理端暴露。

## 新增生成契约

`GET /api/app/messages` 返回权威完整 UIMessage 历史：对话转录存在 pi-durable 的条目里（`app.user` / `app.assistant`），Next 侧经 harness `/messages` 读回，没有自己的消息表。`GET /api/app/generation` 返回生成、构建、完成、失败或取消状态。`POST /api/app/generation/cancel` 请求取消当前任务。

聊天使用 SDK POST 流式协议，不保留旧 GET EventSource 适配。重复请求 UUID 被拒绝再次执行，同一应用写操作使用数据库租约排除并发。服务进程中断后，租约到期，状态读取与后续提交会将旧任务明确标记为失败。

## 有意保留的运行差异

应用创建恢复同步模型选择生成类型，首页只提交初始需求；显式类型仍供 API 调用使用。关键词路由仅限显式 fixture 测试模式。登录与角色管理不依赖旧 Spring Redis 会话。

旧数据以经过校验的副本导入，保留业务主键。导入在停止平台写入的维护窗口进行，记录和本节点雪花发号下界一起提交；冲突整体回滚，不覆盖目标记录。副本格式只含 `users` 与 `apps`（旧文本历史随换 Postgres 放弃，见 `docs/plans/pi-durable-m4.md`）。当前 TS 节点明确采用数据中心 0、机器 0，并通过同一数据库持久化协调，不复现原 JVM 的 MAC 与 PID 推导。旧 Java 的最终快照需冻结后再导入，不能把未参与协调的发号器视为具有共同唯一性保证。模型完整工具消息存储于专用 TS 表，旧文本历史在首次生成事务中转换，不虚构旧工具调用。

页面样式使用集中式 `src/app/globals.css`，未采用计划中的 CSS Modules。八个原 URL 保留，桌面首页、桌面聊天和 390px 移动聊天经过截图及浏览器断言核对。未执行旧、新平台的逐像素对比。

生成源码和发布内容由独立预览来源公开读取。私有的是聊天历史及管理操作，不把来源隔离当作静态资源授权。旧六字符发布键可在复制后的发布目录中访问。仅复制未发布的旧源码不会建立新的 ready 任务；预览取决于有效入口文件，已有 HTML 或 Vue `dist/index.html` 可直接预览。Vue 源码在每次部署前重新构建，构建失败不覆盖旧发布产物。

封面改为存储在 `runtime/covers/`，当前未接入 COS。生产构建使用标准 `next build` 和 `next start`，运行目录及 `.env` 排除在依赖追踪之外。没有执行公网部署或正式切换。

自动化模型使用显式 fixture，真实模型接口与对象存储仍缺少验收凭据。继承父模型的检查不能称为跨模型独立评审。

## 旧产物与封面迁移

`npm run db:import` 支持在导入数据库记录的同时迁移旧文件产物，避免出现只有应用记录、没有源码、发布或封面的状态。产物迁移是可选步骤，入口参数如下。

```
npm run db:import -- runtime/import/snapshot.json \
  [--artifacts <旧项目根目录>] [--covers <封面目录>] [--strict]
```

- 位置参数为快照文件，必须位于 `runtime/import/`，超过 64 MiB 时拒绝。
- `--artifacts <旧项目根目录>` 指向冻结的旧 Java 工作目录；脚本只读其中内容，不修改旧目录。缺省时不迁移任何文件，只导入数据库记录，`app.cover` 保持快照原值，数据-only 导入仍然可用。
- `--covers <封面目录>` 可选，必须与 `--artifacts` 一起使用，默认 `<旧项目根目录>/covers`。
- `--artifacts` 与 `--covers` 缺少目录参数（或下一个 token 仍是 `--` 开头的标志）时直接报错，不会退化为 data-only。
- `--strict` 可选，发现任何缺失产物即中止导入；缺省只输出缺失报告并继续。

### 源目录约定

脚本按 `<旧项目根目录>` 的固定布局读取，与旧 Java `AppConstant` 一致。

- 源码：`code_output/{codeGenType}_{appId}/`，对应旧 `tmp/code_output`。只复制快照中出现的应用；`vue_project` 连 `dist/` 一起复制，`node_modules` 等运行依赖及 `.git`、构建缓存不搬迁。
- 发布：`code_deploy/{deployKey}/`，对应旧 `tmp/code_deploy`，复制到新 `runtime/deploy/{deployKey}/`。
- 封面：`<封面目录>/{deployKey}.png`。旧封面原本上传 COS，脚本不访问 COS 或任何网络；由维护者事先把截图按发布键命名放入该目录。

旧 Java 的封面是 COS URL，新版由本地来源提供 `{previewOrigin}/covers/{deployKey}.png`。迁移时按发布键把 `app.cover` 改写为新来源地址；缺少发布键或缺少暂存截图时，只在缺失报告中列出，缺省不改写该字段。

### 安全与一致性

- 只复制当前快照关联的产物；不在快照中的应用目录、发布键与封面不迁移。
- 冲突 fail closed：目标已存在时在预检阶段中止，不覆盖任何已有用户数据，也不产生部分迁移。
- 逐文件检查符号链接、越界路径，以及 `.env*`、`.paimeng-*`、`.npmrc`、`.yarnrc`、`.ssh` 等敏感项。旧根目录按用户给定路径 canonical 化后允许，但 `code_output`、`code_deploy` 等树内祖先目录若为符号链接则拒绝（校验 `realpath(源) === 记录路径`）。
- 限制目录深度、单文件 20 MiB、总计 256 MiB、最多 4096 个文件；源码、发布、封面共用同一次导入的总量预算，不由单个条目重置。
- 复制先写入目标同级的临时目录，再原子重命名，中断时清理临时目录。
- 数据库与文件不在同一事务。执行顺序为：预检与文件复制完成后才提交数据库事务。数据库连接或事务失败时回滚本次新建的目标目录，只删除本次创建的产物，不动已有用户数据；文件复制失败时数据库事务不会开始。数据库提交后进程立即崩溃，只会同时留下已提交记录与已就位文件，不会出现半条记录。
