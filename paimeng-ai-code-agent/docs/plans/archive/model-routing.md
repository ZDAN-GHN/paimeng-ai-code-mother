# 模型统一管理与动态配置实施计划

> 归档：记录当时的设计、迁移与验收。当前行为见[部署说明](../../pi-durable-deployment.md)与[模型配置](../../provider-convergence.md)。

状态：已获批准并实施。步骤一至步骤五完成；步骤六实现与本地验证已完成，是否勾选由父级在独立复核后决定。

## 目标与已确定需求

在 `paimeng-ai-code-agent/` 内沿用 AI SDK，建立统一的模型配置与项目别名组件。管理员可以在页面修改模型配置，无需重启服务；正在生成的任务继续使用启动时的模型和参数。

用户已确定的需求：

- 配置保存在 MySQL 表中。
- 提供管理端编辑界面。
- 普通修改默认通过 5 秒 TTL 生效。
- 支持手动立即生效。

本计划将以下具体实现方案一并提交审查：三张配置表；两个业务别名；通过共享刷新序号支持跨实例手动生效；密钥留在环境变量；配置读取故障时最多使用 60 秒内的有效旧快照。

## 用户可见行为

| 场景 | 实现后的行为 |
| --- | --- |
| 编辑提供商或别名并保存 | 服务保持运行；DB 正常时，超过 5 秒后开始解析的新请求使用更新后的配置 |
| 点击“立即生效” | 操作成功后开始解析的新请求跳过 TTL，使用该版本或更新版本，包括其他服务实例 |
| 点击“保存并立即生效” | 保存与刷新序号在同一事务提交 |
| 任务已开始生成 | 整个 Agent 工具循环保持原模型、参数和密钥绑定，不中途换模型 |
| 两名管理员同时编辑 | 第二个过期版本的保存返回 409；保留表单内容并提示重新加载 |
| 配置地址或模型名填错 | 本地可识别的错误在保存前拒绝；上游才能识别的错误可能导致新调用失败，页面不会把配置校验成功描述为模型测试通过 |

“立即生效”以**新请求开始解析模型**为边界。已开始解析的请求可以继续用原绑定；空闲实例在下一次解析时加载，不需要提前唤醒。生效保证以 MySQL 可用为条件。

## 范围与实现约束

只修改 `paimeng-ai-code-agent/`。沿用现有 MySQL、Drizzle、Zod、AI SDK、Ant Design 和管理员鉴权，不新增独立网关进程。第一版适配现有 OpenAI-compatible 文本协议。

交付同时包含后端配置、管理 API、管理页面、初始化方式、测试与使用文档。图片生成、预算计费、模型自动容灾、任意上游专有协议和 Java 侧统一管理不在本次范围内。

实现与验证期间不修改 `.env`、开发库或旧项目，不调用真实模型或 COS，不提交或推送 Git；保留根目录原有 139 条暂存删除及其他用户改动。数据库迁移只在专用测试库验证，提供开发/部署环境的迁移步骤。

## 方案

### 1. 配置与别名

新增 `migrations/006_model_registry.sql` 和 `src/server/schema.ts` 中对应定义，保持旧迁移文件不变。

| 表 | 保存内容 |
| --- | --- |
| `ts_model_provider` | id、名称、适配器、baseURL、密钥环境变量引用、兼容选项、启用状态与时间 |
| `ts_model_alias` | 项目别名、提供商引用、上游模型名、能力声明、调用参数、启用状态与时间 |
| `ts_model_config_state` | 固定一行，保存 `revision` 与 `refreshEpoch` |

第一版必需别名为 `codegen.default`（代码生成，要求流式文本和工具调用）及 `route.classify`（生成类型分类，要求可验证的结构化输出）。两者可指向相同或不同模型。提供商标识与别名创建后保持稳定；真实模型名只进入配置层和 SDK 适配层。

共享 schemas 严格限制字段与参数范围；API 版本值使用十进制字符串。所有配置写操作锁定状态行，检查 `expectedRevision`，校验候选完整配置，再写入并递增版本。必需别名不能被删除或禁用，不能指向禁用的提供商；被引用的提供商不能删除。

### 2. SDK 适配与密钥

使用 `createOpenAICompatible` 构造提供商，使用 `customProvider` 按项目别名注册模型。调用参数通过 SDK 的默认设置中间件或明确调用参数应用，避免把 temperature 等参数错误传给 `.chatModel()`。

密钥只在服务端从已允许的环境变量名称解析；默认允许 `AI_API_KEY`，新增部署配置 `MODEL_API_KEY_ENV_ALLOWLIST` 声明其他允许的模型密钥引用。管理端和 API 仅返回引用名称与当前实例的已配置状态，不返回明文。热切换可以选择已有密钥引用，修改环境变量里的值仍需更新进程环境。

兼容选项仅开放当前 SDK 支持且有 schema 的设置；请求或响应特殊处理通过服务端命名适配代码实现。配置表不存可执行脚本。地址校验遵循设计文档中的 HTTP(S)、无内嵌凭据及部署允许名单约束；本地受控测试端点单独允许。

### 3. TTL 与立即生效

进程持有不可变快照及别名注册表。普通保存递增 `revision`；完整配置的缓存默认 5000 ms，到期后由下一次解析触发加载。缓存年龄以一致性读取开始时间为基准，慢加载不能让旧数据获得额外 5 秒有效期。

每次分类或生成任务开始解析时，先向 MySQL 读取共享 `refreshEpoch`；该小查询不使用 5 秒缓存。手动生效递增 `refreshEpoch`，其他实例下一次解析发现变化后必须等待新快照，不再等待 TTL。因此本版不需要 Redis 通知连接。

完整快照的状态行、提供商和别名在同一个一致性读事务中加载。全部校验和构造成功后一次替换引用。并发刷新共享加载 Promise，但每个请求都检查结果满足自己已观察到的刷新序号；版本不能倒退，慢加载不能覆盖新快照。

### 4. 故障边界

首次加载失败且没有快照时返回 503。暂时的 DB 读取故障，且未观察到更高刷新序号时，允许使用距成功读取不超过 60 秒的旧快照并标记降级；设置短退避，失败不能延长旧快照年龄。

已观察到更高刷新序号却无法加载时返回 503。正常读到的无效配置、禁用状态不能被旧快照掩盖。上游鉴权、限流或协议错误沿用现有调用错误处理，不自动换模型、不重放已执行的工具操作。

## 升级兼容与部署

迁移只建表与共享状态，不在 SQL 写真实模型名或密钥。提供显式、幂等的初始化脚本及 npm 命令，部署时先迁移再初始化。

迁移已完成但配置尚为空时，临时将现有 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY` 映射为两个业务别名，管理页面提示需要初始化。DB 不可读或缺表属于部署错误，不能当成空表回退。初始化后的候选写入必须始终保留两个必需别名，以避免回退到 env。

DB 初始化后 DB 成为唯一配置来源；`AI_BASE_URL` 与 `AI_MODEL` 只用于空表兼容和初始化，`AI_API_KEY` 继续作为密钥引用。普通编辑无需重启。部署变更本身及新增适配器仍走既有代码发布流程。
